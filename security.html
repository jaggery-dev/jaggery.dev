Security

What Jaggery listens on, what it sends out, how machines come to trust each other, and what isn't protected yet. We'd rather you read this before installing than find out later.

What it listens on

PortWho can reach itWhat
80your home networkThe page and ai.local, when the machine allows it. On Linux the installer grants just that, not root.
7373your home networkThe same page, ai.local and the folder server at ai.local/mcp, and what machines show each other before they trust each other.
7374approved machines onlyMutual TLS between Jaggery machines.
5353/udpyour home networkmDNS: finding machines, answering for jaggery.local, ai.local and your apps' names.

Nothing is opened on your router. If a firewall is on, the installer opens these to your local network only.

What leaves your house

  1. Update checks. Each machine asks GitHub for a new release every 30 minutes. jag update --policy off stops it.
  2. Hosted models, only if you add one, and only to the providers and models you list, up to the spending cap you set. Every request is kept word for word: jag outbound.

Nothing else. No telemetry, no account, no crash reports.

How machines trust each other

A code, or your approval.
Seeing a machine on the network doesn't make it trusted. It joins with a six-word code from jag invite, which works once and expires, or when you run jag approve.
Its own keys.
Each machine makes a key pair the first time it runs. Machines remember each other's keys and talk over mutual TLS.
New models wait.
A model that turns up later isn't served on ai.local until you approve it, and approval is tied to its files.
Updates are signed.
Each machine installs a build only if it carries Jaggery's signature, even when it comes through another machine in the house. Machines update one at a time, and a build that won't start is rolled back.
Shared folders stay put.
Read-only unless you say otherwise. Hidden files and key files are never served. Old versions are kept for 30 days, and every access is logged.

Web pages and the internet

Trusting the people in your house doesn't mean trusting every web page they open. Jaggery answers only devices on your home network, only when it's asked for by a local name such as jaggery.local or by its address, and it refuses a web page's attempts to change anything. A page on the internet can't use your models or read your shared folders through someone's browser, and a machine with a public address doesn't answer the internet.

What isn't protected yet

  • Everything on your home network is trusted.Like a printer: anyone on it can use ai.local, your shared folders and any hosted allowance, up to its cap. There are no accounts. Put guests and smart devices on a separate network.
  • Another device can answer for ai.local.The names work over mDNS, which any device on the network can answer. Each machine listens for this and warns on the page and in jag doctor, but it can't stop it. Apps that hold secrets can use a machine's own name instead.
  • Text can steer an AI.A file in a shared folder, or a reply from a hosted model, can carry instructions written for an AI, and an agent reading it may follow them. Jaggery doesn't filter for this. That's why folders are read-only unless you say so, every change can be undone, and nothing an agent can reach changes who or what the house trusts.
  • The page has no sign-in.It shows your machines and activity. It can't change anything.
  • Local names are plain HTTP.Traffic between Jaggery machines is encrypted; traffic from your phone to jaggery.local isn't.
  • Releases are signed with a key, not yet keyless.Each machine installs only builds signed with Jaggery's key. Signing tied to the public build log is planned for 1.0.

Found a problem?

Please write to hello@jaggery.dev with "security" in the subject, rather than posting it publicly. Tell us what you found and how to reproduce it. A person will reply within two working days, agree a fix and a date with you, and credit you unless you'd rather not be named.
