Every computer in your home, working as one.

Jaggery is a small, open-source program you run on each computer in your house. They find each other, show up on one page, and share their AI models through one address. No account. Nothing to configure.

$ curl -fsSL https://jaggery.dev/install | sh

On each computer: Linux, a Raspberry Pi, or a Mac with Apple silicon. Read the script first: it checks the build against signed checksums before installing it as a service. More about installing.

Two commands to add a machine

Ask a machine that's already in the house for a code, then type it on the new one. That's the whole setup.

desktop $ jag invite
on the machine you want to add, run:

    jag join amber-attic-barley-brook-basil-acorn

the code works once, until 18:40.

laptop  $ jag join amber-attic-barley-brook-basil-acorn
looking for the machine that issued the code...
joined the house through desktop
both machines now trust each other.

Then open jaggery.local on any phone or laptop at home. In our tests, the new machine was on the map 12 seconds after the code.

What you get

jaggery.local

One page for the house

Every machine, its memory, disks and GPU, and the apps it runs, like Jellyfin, Immich and Home Assistant. Works on a phone.

chat.local

Short names for your apps

Give an app a name once, and every device in the house opens it by that name, whichever machine and port it's on.

ai.local

One address for AI

Point a chat app or editor at it once. Each request goes to the machine that has the model ready, or ran it fastest. Ollama, LM Studio and llama.cpp today.

ai.local/mcp

Folders for models and agents

Lend a folder on any machine, or a NAS, to your AI apps. Read-only unless you say so, and every change can be undone.

jag outbound

Hosted models, if you want them

Add a provider you choose, with a spending cap. Every request that leaves the house is kept word for word.

jag activity

Nothing out of sight

Who used which model, on which machine. Every file an agent read or changed, with old versions kept for 30 days.

What Jaggery will not do

  • Ask you to sign up. There is no account with us, now or later.
  • Report on you. No telemetry. Jaggery doesn't tell us about you, your house or how you use it.
  • Touch your router. Nothing is opened to the internet. Everything stays on your home network.
  • Trust a stranger. A machine joins only with a one-time code or your approval. Machines talk to each other over mutual TLS.
  • Serve a model you haven't seen. A new model in the house stays off ai.local until you approve it.
  • Take over. Jaggery finds what you already run. It doesn't install apps or replace your setup.

What leaves your house

  1. Update checks. Each machine asks GitHub for a new release every 30 minutes. Every release is signed, and each machine checks the signature before it installs one. Machines update one at a time, and a build that misbehaves rolls itself back. jag update --policy off stops it.
  2. Hosted models, only if you add one. You pick the providers and a spending cap. Every request is kept word for word, so you can read it: jag outbound.

Nothing else. One thing to know: Jaggery trusts your home network and everything on it, the way a printer does, so put guests and smart devices on a separate network. Web pages and the internet are refused.

How it works

One small program on each machine.
Linux, Raspberry Pi and Macs with Apple silicon. Windows comes later.
Machines find each other the way your phone finds a printer.
Over mDNS, on your home network. They trust each other only after a one-time code or your approval, and then talk over mutual TLS.
No central server.
One machine answers for jaggery.local and ai.local; if it goes away, another takes over. Any machine can show the page.
Names your devices already understand.
jaggery.local, ai.local and your apps' names work on phones and laptops without setup.
It looks after itself.
Updates arrive one machine at a time and undo themselves if something goes wrong. jag doctor checks the machine and its network and tells you what to type to fix what fails.
Open source.
Written in Go, Apache-2.0. The code is on GitHub, with the long version of this.

How it compares

Tailscale, ZeroTier
They join your machines into one network across the internet. Jaggery works inside the home network you already have, with no account, and adds the page, the names and AI routing. It runs happily alongside Tailscale.
Avahi, Bonjour
They give machines .local names. Jaggery uses the same mDNS, and adds trust between machines, names for apps, and one page.
Homepage, Homarr, Dashy
Dashboards you write by hand. Jaggery finds the machines and apps itself.
LiteLLM, Open WebUI
LiteLLM is a proxy you configure with your providers, and Open WebUI is a chat app. Jaggery finds the runtimes on every machine and routes between them; point Open WebUI at ai.local and it sees the whole house.
exo
It splits one large model across machines. Jaggery sends each request to one machine that can run the model whole.

Questions

Is it safe to run on my network?

Jaggery trusts your home network and everything on it, the way a printer or a media server does: anyone on it can use ai.local, the page and any folders you share. So put guests and smart devices on a separate network, and don't run it on a network you don't control. Web pages and the internet are refused, machines join only with a code, and updates must carry Jaggery's signature. The details, including what isn't protected yet, are on the security page.

Do I need a GPU, or AI at all?

No. Without an AI runtime you still get the page and the names. If a machine runs Ollama, LM Studio or llama.cpp, its models appear at ai.local for every device in the house. A GPU makes them faster, but small models run fine on a CPU.

What does it send to the internet?

Each machine asks GitHub for a new release every 30 minutes, and jag update --policy off stops it. Hosted models are used only if you add a provider. Nothing else: no telemetry, no account, no crash reports.

Does it work with Tailscale?

Yes, side by side. Jaggery accepts requests from Tailscale's addresses, and a machine that isn't on the home network, such as a cloud machine over a VPN, can join with jag join <code> --at <address>.

What about phones?

The page works in any phone's browser. .local names work on iPhones; on Android they depend on the version and the browser, and we'd like to hear what yours does (issue #18).

And Windows?

Not yet (issue #17). Run Jaggery on your other machines, and Windows apps can still use ai.local and open the page.

How do I remove it?

curl -fsSL https://jaggery.dev/install | sh -s -- --uninstall removes the service and the program, and keeps the machine's identity so it can rejoin. To remove that too, delete ~/.config/jaggery on Linux or ~/Library/Application Support/jaggery on a Mac.

Who makes it, and what does it cost?

Jaggery is an independent open-source project with one maintainer for now. It's free, under the Apache-2.0 licence, with no account and nothing to pay. Help is welcome: see how to contribute.

Why “jaggery”?

Jaggery is unrefined sugar, made at home in kitchens across South Asia. Simple, honest, a little sweet. That's how we want the computers in your home to feel.

The command is just jag.

Install it

On each computer: Linux (including a Raspberry Pi 2 or newer) or a Mac with Apple silicon. It asks for your password once, to set Jaggery up as a service.

$ curl -fsSL https://jaggery.dev/install | sh

The script picks the build for your machine, checks it against the release's signed checksums, and installs it. Read it first, or install by hand from the releases. On a Mac, click Allow when macOS asks to let jag find devices on your network.

Then add the next computer with jag invite and jag join, and open http://jaggery.local on any phone or laptop at home. Getting started has the rest.

This is an alpha: it works in our houses, and we want to hear where it doesn't work in yours. Read the known issues first. Then tell us what's in your house and how it went: an issue for anything that broke, Discussions for everything else, or hello@jaggery.dev. A person reads every message.
